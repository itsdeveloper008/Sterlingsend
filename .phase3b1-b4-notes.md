# B4 notes — onboarding, auth, mascot, ss_auth

## Onboarding

- Single step: business name, email, optional logo (`OnboardingWizard`).
- Visible **Skip** sets `localStorage ss_onboarding_skipped=1` and sends the user to `/create-invoice`.
- Completing onboarding clears the skip flag.
- Shown when: `requireOnboarding()` finds no business (History / Account / invoice actions), or user opens `/onboarding`. After first builder save that creates a business, a dismissible “Finish setup” prompt links here.
- Restyled to calm-zone card + `FloatingLabelField` / `FormStatus` tokens.

## Auth pages

- Login remains the dual-pane layout with mascot + Google + password toggle + plain-English errors.
- Signup honors `?redirect=` (same as login) for return-to-builder after pending stash.
- Forgot-password kept; token restyle is light (shared form fields).

## Mascot

- States driven by `?mascotPreview=` for QA: idle, email-focus, password-focus, password-visible, password-error, success.
- Screenshots: run `node scripts/mascot-screenshots.mjs http://127.0.0.1:3103` against a production build (writes `.perf/mascot/*.png`). Includes idle eyes left/right via pointer move.

## ss_auth

- `lib/auth-hint.ts`: set on successful session / Firebase user present; cleared on sign-out / invalid session (`providers/auth-provider.tsx`). Unchanged contract.
