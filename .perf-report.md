### Loader isolation

SessionLoader was changed to show only if still not interactive after **300ms**, and can be skipped via `NEXT_PUBLIC_SKIP_SESSION_LOADER=1` or by seeding `sessionStorage.ss_loader_seen`. Mid-pass LCP gains above already include the delayed loader. A full second 3-run noloader matrix is optional; the loader no longer covers painted content on fast loads.

## P2 — What the 777 kB was

Build route table (baseline): `/tools` and `/tools/[slug]` **778 kB** First Load JS.

Composition (from import graph + later chunk inventory):

1. **Tool engines pulled into the route graph** via `ToolWorkspace` → `processTool` → `@cantoo/pdf-lib`, `pdfjs-dist`, `jspdf`, `jszip`, `tesseract`, `xlsx`, `mammoth`, `pptxgenjs` (async chunks still ~400–650 kB each after split, but no longer in First Load).
2. **Firebase client** via `AuthProvider` → `firebase/auth` on every page.
3. **Marketing shell** always importing search, cookie banner, floating contact, sheets.
4. **Shared Next/React** ~104 kB floor.

Largest residual async chunks (engines, not First Load): see `.perf/chunk-sizes.md` (e.g. 658 kB / 421 kB / 403 kB).

`ANALYZE=true next build` (`npm run analyze`) is wired via `@next/bundle-analyzer`.

Shared-by-all floor: **104 kB**. That alone consumes most of the `/tools` 140 kB budget.

### What moved the needle most

1. Removing engines from initial JS (778 → ~216 on tools).
2. Deferring Firebase until `ss_auth=1` / auth routes / idle.
3. Dynamic MarketingShell extras + deferred tool workspace until “Choose files”.
4. Dynamic PDF download / template dialog / mascot.

### Top remaining causes (with numbers)

1. **Next shared chunks ~104 kB** (React + framework) — hard floor under all budgets.
2. **Marketing shell client island ~90–110 kB** on public routes (header/footer/theme + catalog UI).
3. **LCP still 3.4–5.3 s** on several pages under mobile simulation — Perf scores stay below 90 even when JS transferred dropped ~70%.
